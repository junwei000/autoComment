# AutoComment 本地 OpenRouter 批量评论插件设计

## 目标

把现有付费 SaaS 形态改造成可独立开源的 Chrome Manifest V3 插件。插件不再访问原作者服务器，不再包含支付、积分、用户 ID、CSV 售卖、远程统计或数据库服务。用户在插件内配置自己的 OpenRouter API Key 和模型 ID，批量导入目标 URL 后由插件识别页面内容、生成合适评论、填写表单并按配置提交。

## 产品范围

- 插件图标直接打开 `batch.html`，它是唯一核心页面。
- 批量页面包含 OpenRouter API Key、OpenRouter 模型 ID、推广网站 URL、网站介绍、评论昵称、评论邮箱。
- API Key 只存入 `chrome.storage.local`；其他非敏感设置也统一本地保存，配置不会同步到其他浏览器设备。
- CSV 只读取第一列。首行等于 `url`（大小写不敏感）时作为表头跳过；无表头时首行作为数据。其他列全部忽略。
- 无协议的地址自动补 `https://`；无效 URL 跳过；重复 URL 去重并提示。
- 预览及执行结果中的“站点”显示规范化域名，结果表其他列保持原有含义：序号、结果、错误信息、AI 生成内容、耗时、时间。
- 页面内容区域改为宽版，适合展示配置、URL 预览和执行结果。
- 自动操作仍支持自动生成、自动提交和单页总超时；不保留独立设置页、售卖页或支付入口。

## 架构

### 批量页面

`batch.html` 负责页面结构，`batch.js` 负责设置持久化、CSV 解析、任务队列、结果展示及导出。纯解析和格式化逻辑放入 `lib/batch-utils.js`，以便 Node 测试直接验证。

批量任务严格串行：同一时间只打开一个目标标签页。任务收到最终结果后关闭当前标签页，再启动下一项。

### OpenRouter 调用

`background.js` 是唯一允许向 OpenRouter 发请求的模块。内容脚本通过消息发送当前页面 URL、标题、描述和正文摘要；后台从 `chrome.storage.local` 读取 API Key 与模型 ID，并调用 `POST https://openrouter.ai/api/v1/chat/completions`。请求使用 Bearer 认证、`messages`、用户配置的 `model`、非流式返回和受限输出长度。

OpenRouter 返回的错误正文会被转换为用户可读错误，但日志、页面结果和导出文件中永不包含 API Key。

### 页面识别与提交

`content.js` 保留现有评论框识别、字段填充、非法站点过滤和评论提交能力，移除积分检查、远程统计、远程补偿及原后端消息路径。

提交成功判定采用两阶段协议：

1. 点击提交前，把任务上下文和生成内容写入 `chrome.storage.local`。
2. 点击提交后等待当前文档触发导航/卸载；新页面加载时由恢复逻辑确认成功。如果 10 秒内没有页面刷新，则按提交已触发确认成功。

无论刷新确认还是 10 秒超时，当前任务只确认一次。批量页收到确认后记录结果、关闭标签页并进入下一个任务。单页整体超时继续用于评论框识别和 AI 生成等早期阶段。

## 删除范围

- 删除 `payment.html`、`payment.js`、支付宝设计和测试。
- 删除 `server.js` 与 `api/` 下支付、积分、CSV 售卖/下载、远程生成和统计逻辑。
- 删除后端运维脚本、数据库依赖及生成的插件 ZIP 包。
- 删除选项页、购买入口、用户 ID、积分余额、远程统计上报和作者私有联系方式。
- 更新 manifest、package metadata、README 与隐私说明，使发布内容只描述本地插件和 OpenRouter 请求。

## 错误处理

- 缺少 Key、模型 ID 或必填网站/身份信息时，不允许开始任务并定位到对应字段。
- OpenRouter 401/402/429 等错误显示服务返回信息并将当前 URL 记为失败。
- CSV 为空、格式错误或没有有效 URL 时给出明确提示。
- 页面没有评论框、需要验证码、人工关闭标签页或达到单页超时时保持现有结果分类。
- 页面提交的刷新与 10 秒定时器竞争时使用一次性完成函数，避免重复结果和重复开启下一个标签页。

## 测试

- 单元测试覆盖单列 CSV（有/无表头）、URL 规范化、去重和域名展示。
- 单元测试覆盖 OpenRouter 请求体、错误解析和成功文本提取，确保 Key 只进入 Authorization header。
- 单元测试覆盖提交等待器：页面刷新先到、10 秒超时先到以及只完成一次。
- 静态检查确保仓库不再引用支付、积分、原服务域名和 CSV 售卖接口。
- 使用 `node --test` 跑完整测试，并用 Chrome Manifest JSON 解析检查和 JavaScript 语法检查验证发布文件。
